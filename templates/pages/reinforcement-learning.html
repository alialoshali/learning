Why it exists: for many problems nobody can write down the correct answer, but we can score the outcome: did the robot fall over, did we win the game, did the user like this answer? Reinforcement learning (RL) learns by trial and error from rewards, often delayed many steps after the decision that earned them. It is how AlphaGo learned Go, and through RLHF it is how ChatGPT and Claude learn to give helpful answers.

01The loop: agent, environment, reward

RL has no dataset in advance. An agent interacts with an environment step by step:

  1. it observes the state \(s_t\) (where am I?),
  2. chooses an action \(a_t\) using its policy \(\pi(a\mid s)\),
  3. receives a reward \(r_{t+1}\) (a number, good or bad) and the next state \(s_{t+1}\).

The goal is to choose actions that maximise the total reward over time, not the immediate reward. This is what makes RL hard:

Supervised learningReinforcement learning
the correct answer is givenonly a score, never the correct answer
feedback right awayfeedback can come many steps later (credit assignment)
fixed datasetthe agent’s own actions decide what data it sees (exploration)

02Explore vs. exploit: the multi-armed bandit

The simplest RL problem has one state and \(K\) actions: slot machines (“one-armed bandits”) with unknown average payouts \(\mu_k\). Each pull gives a noisy reward. The agent keeps a running estimate of each arm’s value:

$$Q_k\leftarrow Q_k+\frac{1}{n_k}\big(r-Q_k\big)$$Incremental average: move the estimate a step towards the new reward. This is gradient descent on \((Q_k-r)^2\) with learning rate \(1/n_k\).

Then the dilemma: exploit (pull the arm that looks best so far) or explore (try others, which might be better)? The ε-greedy rule exploits with probability \(1-\varepsilon\) and picks a random arm with probability \(\varepsilon\).

Try it: click the arms yourself, or press Run. Compare \(\varepsilon=0\) (it gets stuck on the first arm that looked good) with \(\varepsilon=0.1\). Tick reveal to see the true means. Regret = the reward lost compared with always pulling the best arm.

Transformer linkSampling an LLM at temperature 0 is pure exploitation (always the top token). During RL fine-tuning, the model must sample with some randomness (temperature > 0) so it can discover better answers. That is exploration.

03Return and discounting: rewards now vs. later

The agent maximises the return, the sum of future rewards, where rewards further in the future count less:

$$G_t=r_{t+1}+\gamma\,r_{t+2}+\gamma^2r_{t+3}+\dots=\sum_{k=0}^{\infty}\gamma^k\,r_{t+k+1}$$
\(\gamma\in[0,1)\)discount factor. A reward \(k\) steps away is worth \(\gamma^k\) of its face value.
\(\gamma=0\)short-sighted: only the next reward counts.
\(\gamma\to1\)far-sighted: patient, plans ahead.

Try it: path A gives +1 every step for 4 steps. Path B gives nothing for 12 steps, then +10. Which is better? It depends on \(\gamma\). Move the slider and watch the preferred path switch. The faded bars show each reward’s discounted value.

Discounting also keeps infinite sums finite. A constant reward of 1 forever is worth \(1/(1-\gamma)\), so \(\gamma\) sets an “effective horizon” of about \(1/(1-\gamma)\) steps.

Transformer linkIn RLHF a whole answer usually gets one reward at the end, and credit must flow back to every token that produced it. This is a credit-assignment problem across hundreds of steps.

04Value functions and Q-learning in a grid world

The action value \(Q(s,a)\) is the expected return if we take action \(a\) in state \(s\) and act well afterwards. It satisfies a recursive relation, the Bellman equation:

$$Q^\star(s,a)=\mathbb E\big[\,r+\gamma\max_{a'}Q^\star(s',a')\,\big]$$Value now = reward now + discounted value of the best next move.

Q-learning turns this into an update after every single step \((s,a,r,s')\):

$$Q(s,a)\leftarrow Q(s,a)+\alpha\Big[\underbrace{r+\gamma\max_{a'}Q(s',a')}_{\text{target}}-Q(s,a)\Big]$$The bracket is the TD error, “target minus prediction”: the same error signal as in regression, with learning rate \(\alpha\).

Try it: the agent ● starts bottom-left and must reach ★ (+10) without falling into ✕ (−10). Each step costs −0.1. Press Train 1 episode to watch it wander, then Train 200. The value (colour) spreads backwards from the goal, one step per episode, and the arrows (greedy policy) form a path. Click cells to add or remove walls, and the agent re-learns.

05Policy gradients: learn the policy directly

Instead of learning values, we can make the policy itself a differentiable model. For example, a softmax over action scores \(\theta\), just like a classifier:

$$\pi_\theta(a\mid s)=\mathrm{softmax}(\theta)_a$$

We want to maximise the expected return \(J(\theta)=\mathbb E_{a\sim\pi_\theta}[R]\). The REINFORCE theorem gives its gradient as something we can estimate from samples:

$$\nabla_\theta J=\mathbb E\big[\,(R-b)\;\nabla_\theta\log\pi_\theta(a\mid s)\,\big]$$\(b\) = baseline (e.g. average reward). It does not change the expected gradient but reduces its noise.

Read it as supervised learning on your own samples: \(\nabla\log\pi(a)\) is the gradient of the cross-entropy loss for “label = the action I took”. Multiply it by how good the outcome was. Good actions become more likely, bad ones less likely.

Try it: three actions with true average rewards 1, 2 and 3 (plus noise). Press Train and watch probability move to the best action. Untick the baseline: learning gets noisier and slower.

Transformer linkThis is the core of RL for LLMs (PPO, GRPO). Sample an answer, score it, and push up \(\log\pi(\text{answer tokens})\) in proportion to (reward − baseline). The gradient flows through the same softmax that generates text.

06RLHF: how chatbots learn what people prefer

Reinforcement Learning from Human Feedback is the final training stage of most chat assistants:

  1. SFT: start from a model fine-tuned on example answers (the reference policy \(\pi_{\text{ref}}\)).
  2. Reward model: people compare two answers, A and B. A network \(r_\phi\) is trained so that preferred answers score higher (Bradley–Terry model):
    $$P(A\succ B)=\sigma\big(r_\phi(A)-r_\phi(B)\big)$$Logistic regression on the difference of two scores.
  3. RL: optimise the policy to get high reward without drifting too far from \(\pi_{\text{ref}}\):
    $$\max_\pi\ \mathbb E_{y\sim\pi}\big[r_\phi(y)\big]-\beta\,\mathrm{KL}\big(\pi\,\Vert\,\pi_{\text{ref}}\big)$$

The solution has a neat closed form, \(\pi^\star(y)\propto\pi_{\text{ref}}(y)\,e^{r(y)/\beta}\). On the right are six possible answers. Lower \(\beta\) and the policy chases reward. Below a certain point it collapses onto answer F, which the reward model overrates (long and flattering, but not actually better). This is reward hacking. The KL penalty \(\beta\) is what keeps the model honest.

Transformer linkAll three stages fine-tune the same Transformer. The reward model is usually a copy of it with a regression head. DPO, a popular newer method, uses the closed form above to skip the RL loop and trains with a simple classification-style loss.

Teach it in one sentence: reinforcement learning improves a policy by trying actions, observing rewards and making rewarded actions more likely, balancing exploration against exploitation. With a reward model built from human preferences, it is the step that turns a text predictor into a helpful assistant.
