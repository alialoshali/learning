Why it exists: to understand language, a model must connect words that can be far apart (“The cat that the dog chased all morning finally slept”) and it must be fast enough to train on trillions of words. The Transformer (2017) does both with one idea, attention: every word looks directly at every other word, all in parallel. It is the architecture behind GPT, BERT and Claude. Every idea here is built from tools you already know as an AI engineer: vectors, dot products, softmax, cross-entropy and gradient descent. Why we needed Transformers

Before 2017, sequences (text, audio) were handled by RNNs: read one token, update a hidden state, read the next. Two problems followed:

  • Sequential: step t needs step t-1, so GPUs cannot process tokens in parallel. Training is slow.
  • Long paths: information from token 1 must survive n−1 updates to reach token n. Gradients vanish (the same issue you meet in deep networks) and early context is forgotten.
Core ideaLet every token look directly at every other token in one step. That operation is attention. The price is n² pairwise comparisons, which is cheap on a GPU because it is one matrix multiplication.

Key terms
Sequence
An ordered list of items, here the tokens of a text.
RNN
Recurrent neural network: reads a sequence one token at a time and keeps a memory vector (see the RNN lesson).
Parallel
Many computations done at the same moment (what GPUs are built for), instead of one after another.
Vanishing gradient
During training, the learning signal shrinks each time it passes through a step, so very early tokens barely affect learning.
Attention
A weighted average where each token decides how much to take from every other token, based on similarity.

Step 1: tokens become vectors

Text is split into tokens (words or word pieces), each mapped to an integer id, then to a learned vector of size d_model using a lookup table E of shape (vocab, d_model).

x_i = E[id_i] X ∈ ℝ^(n × d_model)

Link to what you know: E is just a weight matrix, exactly like a first linear layer on one-hot input. It starts random and is trained by backpropagation, so similar words end up with nearby vectors.

Key terms
Token
A piece of text the model treats as one unit: a word, part of a word (“un”, “break”, “able”) or a punctuation mark. GPT models use about 50,000–200,000 different tokens.
Token id
The integer number of a token in the vocabulary list, e.g. “cat” → 9246.
Vector
A list of numbers, e.g. 768 numbers per token in GPT-2.
Embedding
The learned vector that represents a token. Similar words end up with similar vectors.
d_model
The length of every token vector inside the model (768 in GPT-2, 12,288 in GPT-3).
Embedding table E
A matrix with one row per vocabulary token; looking up row id gives the embedding.
One-hot input
A vector of zeros with a single 1 at the token id. Multiplying it by E selects one row, which is why the lookup is “a linear layer”.

Step 2: self-attention, the heart of the model

Each token vector is projected by three learned matrices into a query (what am I looking for?), a key (what do I offer?) and a value (what I hand over if chosen).

Q = XW_Q, K = XW_K, V = XW_V
Attention(Q,K,V) = softmax( QKᵀ / √d_k ) · V
  1. QKᵀ: dot product of every query with every key, giving an n×n score table (bigger = more similar).
  2. Divide by √d_k so scores don't grow with dimension.
  3. softmax per row turns scores into weights that sum to 1. This is the same softmax as in classification.
  4. Multiply by V: each output is a weighted average of value vectors.
Try it →Click a row label to choose the query token. Drag the slider to divide scores by a bigger number: weights spread out (soft). A small divisor makes them peaky (hard). That is why we divide by √d_k: without it, large d_k makes scores huge, softmax saturates, and gradients vanish. Tick causal mask to see what GPT-style models do (next section).

Key terms
Query q
A vector saying “what am I looking for?”, computed from a token: q = x·W_Q.
Key k
A vector saying “what do I contain?”: k = x·W_K. Query and key are compared.
Value v
The information a token passes on if it is attended to: v = x·W_V.
Dot product q·k
Multiply matching numbers and add them up. Large when the two vectors point in the same direction, so it acts as a similarity score.
Kᵀ (transpose)
K flipped so that QKᵀ computes every query–key dot product at once, giving an n × n table.
√d_k
The square root of the key length. Dividing by it keeps scores in a reasonable range.
Softmax
Turns a row of scores into positive weights that add up to 1 (see logistic regression).
Weighted average
Σ weightⱼ · vⱼ: the output for a token is a blend of the values of all tokens.

Worked example (2-D). Query of “sat” q = (1, 1.2). Keys: “cat” k = (0.2, 1.2), “mat” k = (1, 0.4). Scores: q·kcat = 1·0.2 + 1.2·1.2 = 1.64; q·kmat = 1 + 0.48 = 1.48. Softmax over just these two: e1.64 / (e1.64 + e1.48) ≈ 0.54 and 0.46. So “sat” takes 54% of its new vector from “cat” and 46% from “mat”.

Step 3: word order, positional encoding

Attention treats tokens as a set: shuffle the words and the weights just shuffle too. To inject order we add a position vector to each embedding. The original paper uses sines and cosines of different frequencies:

PE(p,2i) = sin(p / 10000^(2i/d))
PE(p,2i+1) = cos(p / 10000^(2i/d))

Low dimensions oscillate fast (fine position), high dimensions slowly (coarse position), like digits of a counter. Nearby positions get similar vectors, so relative distance is easy to learn. Modern models often learn positions or use rotary embeddings (RoPE), but the goal is identical.

Key terms
Positional encoding
A vector added to each token’s embedding that says where the token is in the text.
Permutation
A reordering. Without positions, attention gives the same result for any permutation of the words.
sin / cos
Wave functions; different frequencies give every position a unique pattern.
RoPE
Rotary position embedding: a modern alternative that rotates query and key vectors by an angle depending on position.

Step 4: multi-head, feed-forward, residuals

Multi-head attention

One attention pattern is too limiting (one token may need syntax and meaning). So we run h smaller attentions in parallel, each with its own W_Q, W_K, W_V of size d_k = d_model/h, then concatenate and mix with W_O. Same cost, more perspectives, like several convolution filters.

MultiHead = Concat(head_1..head_h) · W_O

Feed-forward, residual, LayerNorm

After attention, an ordinary two-layer MLP processes each token separately: FFN(x) = W₂ · GELU(W₁x + b₁) + b₂. Each sub-layer is wrapped as x + Sublayer(x) (a residual connection, the ResNet trick that lets gradients flow through 100+ layers) and normalised with LayerNorm. Attention moves information between tokens; the MLP transforms it within a token.

Minimal attention in PyTorch

import torch, math
import torch.nn.functional as F

def attention(Q, K, V, causal=False):
    # Q,K,V: (batch, heads, n, d_k)
    scores = Q @ K.transpose(-2, -1) / math.sqrt(Q.size(-1))
    if causal:
        n = Q.size(-2)
        mask = torch.triu(torch.ones(n, n), 1).bool()
        scores = scores.masked_fill(mask, float('-inf'))
    weights = F.softmax(scores, dim=-1)
    return weights @ V
How to read this codeQ @ K.transpose(-2, -1) computes all query–key dot products (the n × n table); / math.sqrt(...) is the √d_k scaling; masked_fill(mask, -inf) is the causal mask (e−∞ = 0 after softmax); F.softmax(..., dim=-1) normalises each row; weights @ V takes the weighted average of the values. That is the whole attention formula in 6 lines.
Key terms
Head
One independent attention computation with its own Q/K/V weights. Multi-head = several heads side by side.
Concat
Concatenate: put the head outputs one after the other into one longer vector.
W_O
The output matrix that mixes the concatenated heads back into a d_model vector.
Feed-forward network (FFN / MLP)
A small 2-layer neural network applied to each token separately.
GELU
A smooth version of the ReLU activation function.
Residual connection
Output = input + sublayer(input): the sublayer only adds a correction, and gradients have a direct path backwards.
LayerNorm
Rescales each token vector to mean 0 and variance 1 (plus learned scale/shift), which keeps training stable.

Step 5: how a Transformer is trained

A decoder-only model (GPT, Claude) learns next-token prediction. For text "the cat sat", the targets are: after "the" predict "cat", after "the cat" predict "sat". All positions are trained at once, which is why we need the causal mask: token i may only attend to tokens ≤ i, otherwise it could copy the answer. Set −∞ before softmax and those weights become 0 (tick the box in the widget above).

L = −(1/n) Σ_t log p_θ( x_t | x_<t )

This is ordinary cross-entropy over the vocabulary, the same loss as image classification with vocabulary-sized classes. Training is the loop you know: forward pass, loss, backprop through every matrix (E, W_Q, W_K, W_V, W_O, MLP), then an Adam update, usually with warmup and a decaying learning rate. Perplexity = e^L.

Key terms
Decoder-only
A Transformer that only generates text left to right with a causal mask (GPT, Claude, Llama). BERT is encoder-only (looks both ways).
Next-token prediction
The training task: given all previous tokens, give a probability to every possible next token.
p_θ(x_t | x_<t)
The probability the model with parameters θ gives to the true token x_t, given all tokens before position t.
Cross-entropy
The average −log of the probability given to the correct token.
Adam / warm-up
Adam: gradient descent with momentum and per-parameter step sizes. Warm-up: start with a tiny learning rate and increase it during the first steps.
Perplexity
eloss: roughly “how many tokens the model is choosing between”. Lower is better.

Worked example. Training text “the cat sat”. At position 2 the model sees “the cat” and gives the true next token “sat” a probability of 0.25. The loss at that position is −ln 0.25 ≈ 1.39. If after training it gives 0.8, the loss falls to −ln 0.8 ≈ 0.22. The total loss is the average over all positions of all training texts.

Key takeaways for teaching

Say it in one breathA Transformer turns tokens into vectors, lets every token gather information from the others via softmax(QKᵀ/√d)V, refines each token with an MLP, stacks this many times, and is trained to predict the next token with cross-entropy.

Cost: attention is O(n²·d) in time and O(n²) in memory, which is why long context is expensive and why techniques such as FlashAttention and KV-caching matter in AI engineering.
