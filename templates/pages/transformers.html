Why it exists: to understand language, a model must connect words that can be far apart (“The cat that the dog chased all morning finally slept”), and it must be fast enough to train on trillions of words. The Transformer (2017) does both with one idea, attention: every word looks directly at every other word, all in parallel. It is the architecture behind GPT, Claude, Gemini and Llama. On this page we push the sentence “I love” through a complete, tiny Transformer, every number visible, and watch it predict the next word. The flowchart on the right follows you as you scroll.

Why we needed Transformers

Before 2017, text was processed by recurrent networks (RNNs): read one word, update a memory vector, read the next word. Two problems followed:

  • Sequential, so slow to train. Step t needs the result of step t−1, so a GPU cannot process the words of a sentence at the same time.
  • Long paths, so forgetful. Information from word 1 must survive n−1 updates to reach word n. The learning signal fades along the way (vanishing gradients), so early context is lost.

The Transformer’s answer: let every token look directly at every other token in one step. That operation is attention. The price is \(n^2\) pairwise comparisons, but those are one big matrix multiplication, exactly what GPUs are best at.

Parallel
Many computations done at the same moment instead of one after another.
Attention
Each token computes how relevant every other token is, then takes a weighted average of their information.

The model we will compute by hand

A real GPT has a vocabulary of ~50,000 tokens, vectors of 768–12,288 numbers and 12–96 layers. Ours is the same architecture shrunk until every number fits on the screen:

vocabulary size \(V\)5 tokens: I, love, you, cats, dogs
vector size \(d\) (d_model)4 numbers per token
layers \(N\)1
attention heads \(h\)1, with \(d_k = 2\)
feed-forward width \(d_{ff}\)8 (= 2d here; usually 4d)

The task: given “I love”, predict the next word. The correct answer is “you”. The weights below were picked by hand (round numbers so you can check the arithmetic), so the model starts out untrained: we will see it guess wrong, compute its error, and take one learning step that makes it less wrong.

Three phases① Getting text in (steps 1–3): words → vectors. ② The layer (steps 4–13): attention lets words exchange information; a feed-forward network processes each word. ③ Getting a word out (steps 14–16): vector → probability of every word → pick one.

Phase 1 — Getting text into the modelSteps 1–3: turn characters into vectors of numbers that carry meaning and position.

Step 1 · Tokenize: text → integer ids

A neural network can only compute with numbers. The first step cuts the text into tokens and replaces each token by its id, its row number in the vocabulary:

$$\text{“I love”}\ \to\ [\text{“I”},\ \text{“love”}]\ \to\ [0,\ 1]$$

Real models use subword tokens learned with an algorithm such as Byte-Pair Encoding (BPE): frequent words get one token (“the”), rare words are split into pieces (“tokenization” → “token” + “ization”). This keeps the vocabulary manageable (about 50,000–200,000 entries) while still being able to write any word, including names and typos.

  • Rough rule for English: 1 token ≈ ¾ of a word ≈ 4 characters.
  • Context limits and API prices are counted in tokens, not words.
  • Tokenization has no trained parameters: it is a fixed lookup decided before training.
Key terms
Vocabulary
The fixed list of all tokens the model knows. Each has an integer id.
Subword
A piece of a word, e.g. “ization”. Lets a finite vocabulary spell any word.
BPE
Byte-Pair Encoding: start from single characters and repeatedly merge the most frequent neighbouring pair into a new token.

Step 2 · Embed: look up a vector for every id

Each id selects one row of the embedding table \(E\) (shape \(V\times d\) = 5 × 4). The token becomes a vector of \(d\) numbers:

$$x_i^{\text{emb}} = E[\text{id}_i]$$$$E[0]=[1,0,1,0]\ \ (\text{“I”})\qquad E[1]=[0,1,1,0]\ \ (\text{“love”})$$

Why vectors? An id like 9246 says nothing about meaning; neighbouring ids are unrelated words. A learned vector can place words with similar meaning close together and encode relations as directions (see word embeddings). Every later step works with these vectors.

It is a linear layer in disguise. Write the id as a one-hot vector (all zeros, a single 1 at position id). Multiplying it by \(E\) picks out exactly one row. So the lookup is the matrix product \(\text{onehot}\cdot E\), and \(E\) is trained by backpropagation like any weight matrix.

Trained parameters: \(E\): 5 × 4 = 20 numbers. In GPT-3: 50,257 × 12,288 ≈ 617 million.

Step 3 · Add positional encoding: inject word order

Attention (step 5–8) treats the tokens as a set: shuffle the words and its result is just shuffled too. “dogs love cats” and “cats love dogs” would look identical. So we add a position vector to each embedding. The original Transformer uses waves of different frequencies:

$$PE_{(p,\,2k)}=\sin\!\Big(\frac{p}{10000^{2k/d}}\Big)$$$$PE_{(p,\,2k+1)}=\cos\!\Big(\frac{p}{10000^{2k/d}}\Big)$$\(p\) = position (0, 1, 2, …), \(k\) = which pair of dimensions. With \(d=4\): dims 1–2 use \(p\), dims 3–4 use \(p/100\).
$$x_p = E[\text{id}_p] + PE_p$$

With numbers: \(PE_0=[\sin 0,\cos 0,\sin 0,\cos 0]=[0,1,0,1]\) and \(PE_1=[\sin 1,\cos 1,\sin 0.01,\cos 0.01]=[0.84,0.54,0.01,1.00]\). Adding them gives \(x_1=[1,1,1,1]\) for “I” and \(x_2=[0.84,1.54,1.01,1.00]\) for “love”.

Low dimensions oscillate fast (fine position), high dimensions slowly (coarse position), like the seconds and hours hands of a clock. Trained parameters: none, it is a fixed formula. (GPT-2 instead learns a position table; Llama uses rotary embeddings, RoPE.)

Positional encoding
A vector added to each embedding that says where the token is.

How fast a wave repeats. Each pair of dimensions uses a different one, so every position gets a unique pattern.
RoPE
Rotary position embedding: rotates query and key vectors by a position-dependent angle (used by Llama).

Phase 2 — The layer (repeated N times)Steps 4–10: attention, where tokens exchange information. Steps 11–13: the feed-forward network, where each token “thinks” on its own.

Step 4 · Three views of every word: Q, K, V

Every token vector is multiplied by three learned matrices, giving it three different roles:

$$Q = X W_Q,\quad K = X W_K,\quad V = X W_V$$Each \(W\) has shape \(d\times d_k\) = 4 × 2: 4 numbers in, 2 out.
VectorQuestion it answersAnalogy
query q“What am I looking for?”what you type into a search box
key k“What do I contain / advertise?”the title of a web page
value v“What do I hand over if chosen?”the content of that page

Why three separate matrices? Because what a word looks for is different from what it offers. “love” as a verb looks for its subject; “I” advertises “I am a subject”. Splitting the roles lets the model learn both.

With numbers (click a row on the right to see it): for “love”, \(x_2=[0.84,1.54,1.01,1.00]\) and \(W_Q\) adds dims 1+3 and 2+4, so \(q_2=[0.84+1.01,\ 1.54+1.00]=[1.85,\ 2.54]\).

Note \(d_k=2 \lt d=4\): Q, K, V are projected into a smaller space. With several heads, each head gets its own small space (step 9).

Trained parameters: \(W_Q,W_K,W_V\): 3 × (4 × 2) = 24.

Step 5 · Scores: compare every query with every key

Now every token asks every token: “how well does your key match my query?” The match is a dot product:

$$S = QK^\top\qquad S_{ij}=q_i\cdot k_j=\sum_{m=1}^{d_k}q_{i,m}\,k_{j,m}$$

A dot product is large when two vectors point in the same direction, small or negative when they don’t, so it works as a similarity score. \(K^\top\) (transpose) turns keys into columns so that one matrix product computes the whole n × n table.

With numbers: \(q_2\cdot k_1=(1.85)(2)+(2.54)(2)=8.78\) (“love” looking at “I”) and \(q_2\cdot k_2=(1.85)(2.54)+(2.54)(1.85)=9.40\) (“love” looking at itself).

Trained parameters: none, pure arithmetic on Q and K. But this table is exactly why long context is expensive: 100,000 tokens → 10 billion scores per head per layer.

Step 6 · Divide by √d_k and apply the causal mask

Two adjustments before the scores become weights:

1. Scale. Divide every score by \(\sqrt{d_k}\) (here \(\sqrt2=1.414\)): \(8.78/1.414=6.21\), \(9.40/1.414=6.65\). Why? A dot product adds up \(d_k\) products, so with random vectors its typical size grows like \(\sqrt{d_k}\). With \(d_k=128\), raw scores would be about 11× larger, softmax would give one token ~100% and the rest ~0, and the gradients would vanish. Dividing keeps scores in a reasonable range whatever \(d_k\) is (see the experiment on the right).

2. Causal mask. A language model predicts the next word, so during training token \(i\) must not peek at tokens after it, otherwise it could just copy the answer. We set all scores above the diagonal to \(-\infty\); after softmax \(e^{-\infty}=0\), so those weights become exactly 0.

$$\tilde S_{ij}=\begin{cases}S_{ij}/\sqrt{d_k} & j\le i\\ -\infty & j>i\end{cases}$$

This is what makes GPT-style models “decoder-only” or “causal”. BERT-style encoders skip the mask and look both ways.

Key terms
Causal mask
Blocks attention to future tokens.
−∞ (minus infinity)
A score that becomes probability 0 after softmax.
Saturation
Softmax output stuck at 0/1 so its gradient is ~0: the model stops learning.

Step 7 · Softmax: scores become weights that sum to 1

Each row of scores is turned into attention weights with the softmax from logistic regression:

$$\alpha_{ij}=\frac{e^{\tilde S_{ij}}}{\sum_{m} e^{\tilde S_{im}}}$$

With numbers for “love”: \(e^{6.21}=498\), \(e^{6.65}=773\), sum = 1,271, so \(\alpha=[498/1271,\ 773/1271]=[0.39,\ 0.61]\). “love” will take 39% of its new content from “I” and 61% from itself. “I” can only see itself (mask), so its weight is 100%.

Properties that matter: every weight is between 0 and 1, each row sums to 1, the biggest score gets the biggest share, and only differences between scores matter (adding 100 to a whole row changes nothing).

How much each token takes from each other token; each row sums to 1.

Step 8 · Multiply by V: each word becomes a blend of the others

Each token’s new vector is the weighted average of the value vectors, using its attention weights:

$$Z=\alpha V\qquad z_i=\sum_j \alpha_{ij}\,v_j$$

With numbers: \(z_2 = 0.39\times[2.00,2.00]+0.61\times[1.84,2.55]=[0.78,0.78]+[1.12,1.56]=[1.90,\ 2.33]\).

Now the vector for “love” carries information about “I”. This is the only place in the whole architecture where words communicate with each other. Every other step processes each token on its own.

Because our values are 2-D, we can draw this: the blended vector \(z\) lies on the line between the value vectors, closer to the one with the larger weight.

In real modelsOne head in a trained model might make the pronoun “it” attend 90% to the noun it refers to, so after this step the vector for “it” carries the meaning of that noun. Other heads track the previous word, matching brackets, the subject of a verb, and so on.

Step 9 · Project with W_O (and multi-head attention)

The attention output has only \(d_k=2\) numbers, but the rest of the model works with \(d=4\). The output projection \(W_O\) (2 × 4) maps it back:

$$\text{attn} = Z W_O$$$$[1.90,\ 2.33]\cdot W_O = [1.90,\ 2.33,\ 2.12,\ 2.33]$$

Multi-head attention. Real models run \(h\) attention heads in parallel, each with its own \(W_Q,W_K,W_V\) of width \(d_k=d/h\) (e.g. 12 heads × 64 = 768 in GPT-2). Each head can learn a different kind of relationship. Their outputs are concatenated (placed side by side, back to width \(d\)) and mixed by \(W_O\):

$$\text{MultiHead}(X)=\text{Concat}(\text{head}_1,\dots,\text{head}_h)\,W_O$$

Splitting into heads costs nothing extra: \(h\) heads of width \(d/h\) have the same number of parameters as one head of width \(d\).

Trained parameters: \(W_O\): 2 × 4 = 8.

Step 10 · Add the residual, then LayerNorm

Residual connection. Instead of replacing the token vector with the attention output, we add them:

$$r = x + \text{attn}(x)$$$$=[0.84,1.54,1.01,1.00]+[1.90,2.33,2.12,2.33]$$$$=[2.74,\ 3.87,\ 3.13,\ 3.33]$$

“love” does not lose itself inside “I”: attention edits the vector, it does not replace it. It also gives gradients a direct path back through many layers (see vanishing gradients).

LayerNorm. Then each token vector is rescaled to mean 0 and standard deviation 1, which keeps numbers in a stable range layer after layer:

$$\mu=\tfrac1d\sum_m r_m\qquad \sigma^2=\tfrac1d\sum_m (r_m-\mu)^2$$$$h=\gamma\odot\frac{r-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta$$

With numbers: \(\mu=13.07/4=3.27\), deviations \([-0.53,0.60,-0.14,0.06]\), \(\sigma^2=0.166\), \(\sigma=0.41\), so \(h=[-1.30,\ 1.47,\ -0.34,\ 0.15]\). (The live numbers on the right are computed without intermediate rounding, so the last digit can differ.)

Trained parameters: \(\gamma\) (scale) and \(\beta\) (shift), 4 + 4 = 8; here \(\gamma=1,\ \beta=0\). Many recent models put the normalisation before each sub-layer (“pre-norm”) and use RMSNorm, a simpler variant without the mean.

Step 11 · Feed-forward expand + ReLU (4 → 8)

Attention moved information between words. The feed-forward network (FFN, a 2-layer MLP) now processes each word on its own.

The one rule for vector × matrixMultiplying a vector by a matrix = taking the dot product of the vector with every column. Each column gives one output number. So rows of the matrix = numbers in (must match the vector), columns = numbers out. \(W_1\) is 4 × 8: 4 in, 8 out (expand). \(W_2\) is 8 × 4: 8 in, 4 out (contract). Nothing is stretched or squeezed; only the matrix shape differs.
$$a=\mathrm{ReLU}(hW_1+b_1)\qquad \mathrm{ReLU}(x)=\max(0,x)$$

Read \(W_1\) by columns: each column is one neuron’s input weights, the pattern it is looking for. Neurons 1–4 each read one dimension; neurons 5–8 read combinations of two dimensions, patterns that cannot be seen in any single number. That is why the layer is wider than \(d\).

Then ReLU keeps positive scores and silences the rest. The bias is a learned threshold: neuron 7’s bias of −0.5 means it must score above 0.5 to fire. For “love”, 3 of the 8 detectors stay silent. Without ReLU, \(W_1\) and \(W_2\) would multiply into one 4 × 4 matrix and the FFN would add nothing (tick the box to see it).

Trained parameters: \(W_1\) (4 × 8 = 32) + \(b_1\) (8) = 40.

Step 12 · Feed-forward contract (8 → 4)

The 8 detector outputs must be collected back into a vector of width \(d=4\), so the next step can add them to \(h\). \(W_2\) is 8 × 4:

$$f = aW_2+b_2$$

Key insight: every neuron has two weight vectors. Its column of \(W_1\) says what it listens for; its row of \(W_2\) says what it writes when it fires. Neuron 5 listens for [0,1,1,0] but writes [0, 0.5, 0.5, 0]. These are separate, independently learned decisions.

Two equivalent ways to compute \(f\) (toggle on the right):

  • Row view: each neuron’s row, scaled by how strongly it fired, added up. Silent neurons add nothing.
  • Column view: dot product of \(a\) with each of the 4 columns of \(W_2\). Only 4 columns, so only 4 numbers come out.

With numbers: column 2 = 1.47 + 0.565 + 0.085 + 0.56 = 2.68, so \(f=[0.09,\ 2.68,\ 0.57,\ 0.71]\).

Why expand then contract? The wide middle is a workbench with room for many separate detectors; the narrow width \(d\) is the bus between layers, kept small because every layer and token pays for it. 8 on/off neurons give 2⁸ = 256 firing patterns versus 16 for 4. Researchers see \(W_1\) columns as keys (“does the input match my pattern?”) and \(W_2\) rows as values (“then add this fact”): the FFN is where much of a model’s knowledge is stored.

Trained parameters: \(W_2\) (8 × 4 = 32) + \(b_2\) (4) = 36.

Step 13 · Add the residual, then LayerNorm (end of the layer)

Exactly as in step 10: add the FFN output to its input, then normalise:

$$h_{\text{final}}=\mathrm{LayerNorm}(h + f)$$

With numbers: \([0.09,2.68,0.57,0.71]+[-1.30,1.47,-0.34,0.15]=[-1.21,4.15,0.23,0.86]\); normalised: \(h_{\text{final}}\approx[-1.13,\ 1.60,\ -0.40,\ -0.08]\).

The output has the same shape as the input (n × d). That is what lets us stack layers: layer 2 receives exactly the kind of matrix layer 1 received, and refines it further. GPT-2 small stacks 12 layers, GPT-3 96. Each layer has its own weights. Through the stack, a token’s vector gradually changes from “which word am I?” to “what word should come next?”.

The vectors flowing through the residual connections are often called the residual stream: each attention and FFN block reads from it and adds a small edit to it.

Trained parameters: second LayerNorm γ, β = 8.

Phase 3 — Getting a word outSteps 14–16: turn the last token’s final vector into a probability for every vocabulary word, then pick one.

Step 14 · Unembed: one score (logit) per vocabulary word

To predict the next word we only need the final vector of the last token (“love”). Each vocabulary word gets a score, its logit, from a dot product with an unembedding vector. Here the unembedding is tied to the embedding: \(W_U=E^\top\), so word \(w\)’s detector is its own embedding row:

$$\text{logit}_w = h_{\text{final}}\cdot E[w]$$

With numbers: logit(you) = (−1.13)(1) + (1.60)(1) + (−0.40)(0) + (−0.08)(1) = 0.39; logit(cats) = 1.60 − 0.08 = 1.52.

A large logit means “the final vector points in the same direction as this word’s vector”. GPT-2 ties \(W_U\) to \(E\) to save parameters; Llama keeps them separate.

Step 15 · Softmax over the vocabulary

Softmax turns the logits into a probability distribution over the whole vocabulary (all positive, sum = 100%):

$$P(w)=\frac{e^{\text{logit}_w/T}}{\sum_{u} e^{\text{logit}_u/T}}$$

With numbers (T = 1): \(e^{-1.53}=0.22,\ e^{1.20}=3.32,\ e^{0.39}=1.48,\ e^{1.52}=4.57,\ e^{-1.21}=0.30\); sum = 9.89. So P(cats) = 46%, P(love) = 34%, P(you) = 15%.

The model predicts “cats”: it is wrong. The correct answer “you” got only 15%. That is exactly what an untrained model looks like. Training (after step 16) fixes it.

Temperature \(T\) divides the logits before softmax. \(T\lt1\) sharpens the distribution (more confident, more repetitive text); \(T\gt1\) flattens it (more varied, more random). This is the “temperature” setting of ChatGPT and the Claude API.

Step 16 · Sample a token, append it, and repeat

The model does not output a word directly; it outputs probabilities. To produce text we pick one token:

  • Greedy (temperature 0): always take the most probable token. Deterministic but often repetitive.
  • Sampling: draw at random according to the probabilities. A 46% word is chosen about 46% of the time. Variants such as top-k and top-p (nucleus) only sample among the most likely tokens.

Then the chosen token is appended to the input and the entire pipeline runs again on the longer sequence (new positions, a bigger attention table) to predict the following word. This loop is called autoregressive generation. A 500-word answer from a chatbot means roughly 650 complete passes through the model.

Try it: sample a few times to see the randomness, then press Append: the chosen word is added to the sentence in the top bar, and every step on this page recomputes for the longer sentence. (Our untrained toy model will produce odd sentences.)

KV-cacheWhen generating, the keys and values of earlier tokens do not change, so real systems store them (the “KV-cache”) and only compute the new token’s row. This is why long chats need a lot of GPU memory.

Learning — how the numbers changeRun the pipeline, measure how much probability the true next word got, and push every parameter a little in the direction that would have given it more.

Training: loss, gradient, update

1. The loss. Cross-entropy: the negative log of the probability given to the correct word:

$$\mathcal L=-\ln P(\text{you})=-\ln(0.151)=1.89$$

If the model gave “you” 100%, \(-\ln 1=0\): no loss. As the probability falls towards 0, the loss climbs towards infinity. Confident and wrong is punished hardest.

2. The gradient at the output. With softmax + cross-entropy, the gradient with respect to the logits is simply prediction minus truth:

$$\frac{\partial\mathcal L}{\partial\,\text{logits}}=p-y$$$$=[0.022,\ 0.336,\ \mathbf{-0.849},\ 0.463,\ 0.030]$$\(y\) is the one-hot vector of the correct word [0, 0, 1, 0, 0].

Gradient descent moves against the gradient: “you” (−0.849) is pushed up hard, “cats” (+0.463) is pushed down hardest, words near 0% barely move. The size of each push is exactly how wrong it was.

3. Update the unembedding (learning rate η = 0.1). Each word’s column moves by \(-\eta\,(p_w-y_w)\,h_{\text{final}}\). For “you”: \([1,1,0,1]-0.1\times(-0.849)\times h_{\text{final}}\approx[0.904,\ 1.136,\ -0.034,\ 0.993]\). Its second number rose because \(h_{\text{final}}\) is large in dimension 2: “listen harder to this direction”.

4. Rerun. After one step: P(you) 15.1% → 22.4%, P(cats) 46.2% → 40.7%, loss 1.89 → 1.50. Still wrong, but measurably less wrong. (The live demo on the right computes without rounding intermediate values, so it shows 22.6% and 1.49.) Press Train to keep going: after about 20 steps “you” passes 85%.

5. The gradient keeps flowing. To keep the demo followable we only update \(W_U\). In reality the chain rule carries the signal back through every step: LayerNorm → residual → \(W_2\) → ReLU → \(W_1\) → LayerNorm → residual → \(W_O\) → softmax → \(W_Q,W_K,W_V\) → \(E\). Neurons that were silent (ReLU = 0) get no gradient this step: silent neurons don’t learn. All 144 parameters get their own nudge in one backward sweep.

How real training differsEvery position trains at once: from “I love you” the model gets two examples in one pass (“I” → “love”, “I love” → “you”); the causal mask makes that honest. Batches: gradients from thousands of sentences are averaged before each update. Scale: trillions of tokens, the Adam optimizer, and weeks on thousands of GPUs.

GPT-3 is the same procedure with 175 billion numbers instead of 144. Where do they come from? Per layer, attention has 4 matrices of about \(d\times d\) (Q, K, V, O) = \(4d^2\), and the FFN has 2 matrices of \(d\times 4d\) = \(8d^2\). Hence the rule of thumb:

$$N_{\text{params}}\approx 12\,d^2\,L\;+\;V\,d$$\(d\) = model width, \(L\) = number of layers, \(V\) = vocabulary size. For GPT-3: \(12\times12{,}288^2\times96\approx174\) billion, plus \(50{,}257\times12{,}288\approx0.6\) billion for the embeddings.

Try the calculator on the right. Pick a real model: the breakdown is computed from its published architecture (width, layers, heads, FFN size, vocabulary), and you can change any setting to see where the parameters live. Two things to notice: (1) in big models the FFN holds about ⅔ of the parameters; (2) memory needs 2 bytes per parameter just to store a model in 16-bit precision, and roughly 16 bytes per parameter to train it with Adam.

Key terms
Gated FFN (SwiGLU)
An FFN with 3 matrices instead of 2 (used by Llama); d_ff is reduced to keep the size similar.
GQA
Grouped-query attention: several query heads share one key/value head, shrinking W_K, W_V and the KV-cache (Llama 2 70B).
RMSNorm
A simpler LayerNorm with only a scale γ (d numbers) and no shift.
Learned positions
A trained table of position vectors (GPT-2: 1,024 × d). Sinusoidal and RoPE add no parameters.
