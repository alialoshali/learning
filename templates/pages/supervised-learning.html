Why it exists: for many problems we already have examples with the correct answer: house sales with prices, emails marked spam, photos tagged “cat”. Supervised learning uses these (input, correct answer) pairs to learn a function that gives the answer for new inputs. It is the most widely used kind of machine learning, and it is the training signal inside every language model: “here is the context, the correct next token is X”.

01The setting: learn a function from labelled examples

We are given a training set of \(N\) labelled examples and want a function that maps inputs to outputs:

$$\mathcal D=\{(x_1,y_1),\dots,(x_N,y_N)\}\qquad\text{find } f_\theta \text{ such that } f_\theta(x)\approx y$$
SymbolMeaningExample
\(x\)input / features (a vector)size and age of a flat
\(y\)label / target (the correct answer)its sale price
\(f_\theta\)model with parameters \(\theta\)a line \(w^\top x+b\)
\(\hat y=f_\theta(x)\)prediction€212,000

There are two main types, depending on what \(y\) is:

  • Regression: \(y\) is a number (price, temperature). The model draws a curve through the data.
  • Classification: \(y\) is a category (spam/not spam, digit 0–9, next word). The model draws a boundary between the classes.

02Loss functions: how wrong is a prediction?

The loss \(\ell(\hat y, y)\) turns one prediction into a penalty. Training minimises the average loss over the training set:

$$\mathcal L(\theta)=\frac1N\sum_{i=1}^N \ell\big(f_\theta(x_i),y_i\big)$$
LossFormulaUsed for
Squared error (MSE)\((\hat y-y)^2\)regression; big errors punished heavily
Absolute error (MAE)\(|\hat y-y|\)regression robust to outliers
Hubersquared when small, absolute when largea compromise between the two
Cross-entropy\(-\log \hat p_{\,y}\)classification (probabilities)

Why the choice matters: squaring makes one huge error count as much as many small ones. Drag the outlier slider and compare the MSE line (purple) with the MAE line (green). The MSE line is pulled towards the outlier; the MAE line hardly moves.

Where the losses come from. MSE is what you get from maximum likelihood if you assume Gaussian noise on \(y\). Cross-entropy is maximum likelihood for categories. So choosing a loss is the same as choosing an assumption about the noise.

Transformer linkLLMs use cross-entropy, \(-\log p(\text{correct token})\), averaged over every position of every sequence. A loss of 2.0 means that on average the model gave the correct token a probability of \(e^{-2}\approx 0.135\).

03A first model: k-nearest neighbours

The simplest supervised learner just remembers the training set. To label a new point, it finds the \(k\) closest training points and takes a majority vote:

$$\hat y(x)=\text{majority}\{\,y_i : x_i\in \mathcal N_k(x)\,\}\qquad d(x,x_i)=\lVert x-x_i\rVert_2$$
  • k = 1: a very jagged boundary that fits every training point, including the noise (overfitting).
  • Large k: a smooth boundary that may ignore real detail (underfitting).

Soft version (tick the box): instead of a hard vote of \(k\) neighbours, every training point votes with a weight that decays with distance, normalised by a softmax:

$$w_i=\frac{e^{-d(x,x_i)^2/\tau}}{\sum_j e^{-d(x,x_j)^2/\tau}},\qquad \hat p(x)=\sum_i w_i\,y_i$$

Move the mouse over the plot to see which training points the query (★) is looking at. Its neighbours are highlighted.

Transformer linkThe soft version is attention. A query compares itself with every key (here: training points), turns the similarities into weights with a softmax, and returns the weighted average of the values (here: labels). The difference in a Transformer is that the similarity is a learned dot product \(q\cdot k\) instead of a fixed distance.

04Choosing the model: validation curves

Training error alone is misleading: k-NN with \(k=1\) always scores 100% on its own training data. To choose a hyper-parameter such as \(k\), we measure error on a separate validation set.

$$k^\star=\arg\min_k\ \text{Err}_{\text{val}}(k)$$

The plot shows both error curves as \(k\) changes. Read it from right to left:

  • Large \(k\) (right): both errors are high, so the model is too simple.
  • Small \(k\) (left): training error falls to 0 but validation error climbs back up. That gap is overfitting.
  • The best \(k\) sits at the bottom of the validation curve.

With small datasets one split is noisy, so we use k-fold cross-validation: split the data into 5 parts, train on 4, validate on 1, rotate, and average.

Transformer linkWhen training an LLM, you cannot afford to try many sizes. Engineers fit scaling laws (validation loss vs. model size and data) on small runs and extrapolate. It is the same idea as this plot, done at very large scale.

05Regularisation: keep the weights small

A flexible model can fit noise by using huge, finely balanced weights. Regularisation adds a penalty for large weights to the loss:

$$\mathcal L_{\text{reg}}(\theta)=\underbrace{\frac1N\sum_i(\hat y_i-y_i)^2}_{\text{fit the data}}+\underbrace{\lambda\lVert\theta\rVert_2^2}_{\text{stay simple}}$$

\(\lambda\) is a hyper-parameter: 0 means no penalty, large means “prefer weights close to 0”. On the right, a degree-12 polynomial is fitted to 12 noisy points. Move \(\lambda\) (log scale) and watch two things:

  • the curve smooths out, and
  • the coefficient bars underneath shrink, from thousands down to small values.

In gradient descent the penalty adds a term \(2\lambda\theta\) to the gradient, which shrinks every weight a little at every step. This is why it is also called weight decay.

Transformer link“AdamW”, the standard optimizer for Transformers, is Adam plus Weight decay. Dropout (randomly switching off neurons during training) is another regulariser used in Transformers.

06Measuring a classifier: beyond accuracy

A classifier outputs a score (for example \(\hat p\)), and we choose a threshold: above it, predict “positive”. Every prediction then falls into one of four boxes, the confusion matrix:

$$\text{precision}=\frac{TP}{TP+FP}\qquad\text{recall}=\frac{TP}{TP+FN}$$$$F_1=\frac{2\cdot\text{precision}\cdot\text{recall}}{\text{precision}+\text{recall}}$$Precision: of the cases flagged, how many were real? Recall: of the real cases, how many did we catch?

Experiments:

  1. Move the threshold. Recall and precision trade off against each other. The dot moves along the ROC curve.
  2. Set the positive rate to 1% (e.g. a rare disease). A model that always says “negative” gets 99% accuracy and is useless. Accuracy misleads on imbalanced data.
  3. Increase the separation: a better model pushes the ROC curve to the top-left corner, giving AUC → 1.
Transformer linkLLM evaluation uses the same tools: precision and recall for retrieval in RAG systems, AUC for safety classifiers, and calibration (does “90% sure” mean right 90% of the time?) for model confidence.

07Supervised fine-tuning (SFT) of a language model

After pre-training, a chatbot is taught to follow instructions with supervised fine-tuning. People write example conversations (prompt → ideal answer), and the model is trained to produce the answer. These are ordinary labelled pairs:

$$x=\text{prompt},\qquad y=\text{ideal response}=(y_1,\dots,y_T)$$$$\mathcal L=-\frac1T\sum_{t=1}^{T}\log p_\theta\big(y_t\mid x,\,y_{\lt t}\big)$$
  • The model reads the prompt and the correct answer so far (teacher forcing) and must predict the next answer token.
  • The loss is applied only to the answer tokens. The prompt tokens are masked, because we want the model to learn to answer, not to write user questions.
  • Each answer token is one classification problem over the vocabulary, so a 10-token answer gives 10 supervised examples.

Click a token on the right to see what the model sees as input and what it must predict.

Transformer linkThis is supervised learning with exactly the cross-entropy loss from logistic regression. It is applied to a Transformer, and one example sentence gives many training targets at once.

Teach it in one sentence: supervised learning fits a function to examples whose answers are known, by minimising a loss that compares predictions with those answers, while checking on held-out data that it also works on new inputs.
