Why it exists: real problems often ask for a class or a probability, not an unrestricted real number. Logistic regression is the smallest neural network that does this: one linear layer + a squashing function, trained with cross-entropy and gradient descent. Every idea here reappears inside a Transformer — look for the orange “Transformer link” boxes. All plots are interactive: drag, click, train.

0. The data: what exactly are we classifying?

Before any algorithm, look at the raw data. Each row of the table is one example (one student). It has an input x = hours studied, and a label y = the correct answer: 1 (passed) or 0 (failed).

The goal: learn a rule so that for a new student, given only their hours, we output the probability that they pass.

1. Why do we need it? From a straight line to logistic regression

We build logistic regression in four small steps, using the students from Section 0. Click the step buttons on the right and read the explanation under the plot.

  1. Fit a straight line (ordinary linear regression) to the 0/1 labels.
  2. See where it breaks: it gives impossible “probabilities” (below 0, above 1) and one outlier tilts it.
  3. Keep the line, but change its meaning: it no longer predicts the label, it outputs a score z that can be any number.
  4. Squash the score with the sigmoid, so the output is always a valid probability between 0 and 1.
Before → after, in one lineBefore (linear regression): ŷ = m·x + c, any number.
After (logistic regression): p̂ = σ(w·x + b), always between 0 and 1.
Same straight line inside, plus a squashing function wrapped around it.

Experiment: in steps 1, 2 and 4 drag the outlier slider to the right (a student who studied a lot and passed). Watch the straight line tilt and its 0.5 crossing move, while the S-curve barely changes. That stability is the practical reason we prefer it.

Predicting a category (pass/fail, spam/not spam) instead of a number.
Binary
Exactly two classes, coded as 1 and 0.

A number between 0 and 1 saying how likely something is (0.8 = 80% likely).

The S-shaped function σ(z) = 1/(1+e−z) that squashes any score into (0, 1).

2. The main equation, symbol by symbol

p̂ = σ( w·x + b )  =  1 / ( 1 + e−(w·x + b) )

Read it from the inside out. The whole model is these three stages:

  1. Score. z = w·x + b. A weighted sum of the inputs (a straight line). Any real number.
  2. Squash. p̂ = σ(z). Turns the score into a probability in (0, 1).
  3. Decide. Predict class 1 if p̂ ≥ 0.5 (equivalently z ≥ 0), else class 0.

bbiasthe score when x = 0; shifts the boundary; learned−7: a student needs about 5.4 h to reach score 0
zscore / logitw·x + b, before squashing1.3·6 − 7 = 0.8
p̂predicted probabilitymodel’s belief that y = 1σ(0.8) ≈ 0.69

Several inputs? Then w·x means w₁x₁ + w₂x₂ + … + wₙxₙ: one weight per feature, all summed into one score. With two features (Section 6) the decision boundary is a line in 2-D.

3. The model: one neuron

p̂ = σ(w·x + b)    predict 1 if p̂ ≥ 0.5

w (weight) sets how steep the curve is; b (bias) shifts it. The decision boundary is where p̂ = 0.5, i.e. x = −b/w (dashed line). Move the sliders to fit the ten students by hand and watch the loss number — your goal is to make it small. That number is defined next.

Worked example (use w = 1.3, b = −7)

  • Student with x = 6 h: z = 1.3·6 − 7 = 0.8, p̂ = σ(0.8) ≈ 0.69 → predict “pass” (true label 1 ✓).
  • Student with x = 3 h: z = 1.3·3 − 7 = −3.1, p̂ = σ(−3.1) ≈ 0.04 → predict “fail” (true label 0 ✓).
  • Boundary: z = 0 ⇒ x = 7/1.3 ≈ 5.4 h. Below it we say fail, above it pass.

In the plot, the vertical orange segments are the gaps between the curve and each true label. Good parameters make all those segments short.

Key terms
Weight w
How strongly the input pushes the score up (positive) or down (negative). Large |w| = a steep S-curve = a confident model.
Bias b
A constant added to the score; it moves the curve left/right.
Decision boundary
The input value where the model is exactly 50/50 (z = 0). Students on one side are predicted to pass, on the other to fail.
Accuracy
The share of examples classified correctly.
Parameters = knobsLearning = finding good values for w and b. Here 2 knobs; GPT-scale models have hundreds of billions.
Transformer linkw·x + b is a linear layer (nn.Linear). Transformers stack thousands of them; σ is swapped for softmax or GELU, but the building block is identical.

4. The loss: binary cross-entropy

We need one number saying “how wrong are the probabilities?”. Use maximum likelihood: pick parameters that make the observed labels as probable as possible. For one example, the likelihood is p̂ if y=1 and 1−p̂ if y=0. Taking −log and averaging over N examples:

L = −(1/N) Σ [ y·log p̂ + (1−y)·log(1−p̂) ]

Slide the predicted probability on the right. If the truth is 1 and you say 0.99 the loss is tiny; if you say 0.01 the loss explodes. Confident and wrong is punished hardest.

Reading the formula with numbers

The formula looks scary but each example uses only one of its two terms (the other is multiplied by 0):

  • True y = 1, model says p̂ = 0.69 → loss = −ln(0.69) ≈ 0.37 (small, it was mostly right).
  • True y = 1, model says p̂ = 0.04 → loss = −ln(0.04) ≈ 3.2 (big: confidently wrong).
  • True y = 0, model says p̂ = 0.04 → loss = −ln(0.96) ≈ 0.04 (almost perfect).

The loss L is the average of these numbers over all training examples. Training means making L as small as possible.

Key terms
Likelihood
How probable the observed labels are under the model: p̂ for students who passed, 1−p̂ for those who failed, multiplied over all students.
Maximum likelihood
Choose the parameters that make the observed data most probable.
Logarithm (log, ln)
Turns products into sums and small probabilities into large negative numbers: ln(1) = 0, ln(0.5) ≈ −0.69, ln(0.01) ≈ −4.6.
Cross-entropy
The average −log of the probability given to the correct answer. It is the negative log-likelihood per example.
Convex
A loss with a single valley, so gradient descent cannot get stuck.

Why not squared error? With a sigmoid it gives a bumpy, non-convex surface and vanishing gradients; cross-entropy is convex for logistic regression and has a beautifully simple gradient (next section).

Transformer linkGPT is trained with exactly this loss — cross-entropy between the predicted next-token distribution and the true token (the multi-class version: L = −log p̂correct). “Perplexity” is just eL.
How to read this graph
  • Horizontal axis = the probability p̂ the model gives to “pass”, from 0 to 1. Vertical axis = the loss for one example.
  • Blue curve −log p̂ = the loss if the student really passed (y = 1). Low when p̂ is near 1, explodes as p̂ → 0.
  • Orange curve −log(1−p̂) = the loss if the student really failed (y = 0). The mirror image.
  • Move the slider: the dashed line and the two dots show both losses for that p̂. At p̂ = 0.5 both equal 0.69 (= ln 2): the cost of a coin-flip guess.

5. Training with gradient descent (one feature)

No closed-form solution exists, so we walk downhill on the loss surface. Repeat:

w ← w − η · ∂L/∂w    b ← b − η · ∂L/∂b

Differentiating cross-entropy through the sigmoid, the messy terms cancel and you get:

∂L/∂w = (1/N) Σ (p̂ − y)·x    ∂L/∂b = (1/N) Σ (p̂ − y)
Key terms
Gradient ∂L/∂w
How much the loss changes if w is increased a tiny bit. Negative = increasing w lowers the loss.
Learning rate η
The step size of each update.
Closed form
A direct formula for the answer. Logistic regression has none, so we must iterate.
Error e = p̂ − y
Prediction minus truth for one example; positive = predicted too high.

Read it in words: “error × input”. Each point pushes the boundary away from itself if it is misclassified, proportional to how wrong it is.

One training step with real numbers (our 10 students)

  1. Start at w = 0, b = 0. Then z = 0 for everyone, so every p̂ = 0.5: a flat line.
  2. Errors e = p̂ − y: the 5 failed students have e = +0.5, the 5 passed students have e = −0.5.
  3. Gradient for b = average of e = (5·0.5 − 5·0.5)/10 = 0.
  4. Gradient for w = average of e·x = (0.5·(1+2+3+4+5.2) − 0.5·(4.4+6+7+8+9))/10 = −0.96. It is negative because the passed students have larger x.
  5. Update with η = 0.1: w ← 0 − 0.1·(−0.96) = 0.096, b stays 0. A negative gradient makes w grow, so the curve tilts upward: high x → pass. That is exactly the right direction.

Try it on the right. Top: the S-curve moves as (w, b) change. Bottom: the loss landscape. Every point is one (w, b) pair, orange = high loss, white = low loss. Gradient descent is a ball rolling from (0, 0) down to the white valley. Try a big η (0.3: it overshoots and zig-zags) and a tiny one (it crawls).

How to read these two graphs

  • Bottom: the loss landscape. Each location is one pair of parameters: horizontal = weight w, vertical = bias b. The colour is the loss L(w, b) for that pair: orange = high loss (bad model), white = low loss (good model).

6. The same training with two features

What is the 2-D data?

Now each student has two features: x₁ = hours studied (horizontal) and x₂ = hours slept (vertical). Each dot is one student, blue = passed, orange = failed. The model becomes p̂ = σ(w₁x₁ + w₂x₂ + b) and the decision boundary (where p̂ = 0.5) is a straight line that should separate blue from orange.

The same five steps, now with w₁, w₂ and b

  1. Start with w₁ = w₂ = b = 0, so every p̂ = 0.5 (the model knows nothing).
  2. Predict p̂ for every dot.
  3. Measure error e = p̂ − y for each dot. Example: a blue dot (y=1) with p̂ = 0.5 gives e = −0.5.
  4. Gradient = average of e·x. That tells us which way to nudge each knob to reduce the loss.
  5. Update w ← w − η·gradient. Repeat until the loss curve flattens.

The learning rate η is the step size: too small = slow, too big = overshoots and bounces.

On the right: two classes in 2-D (blue = 1, orange = 0), background shows p̂. Press Step or Run and watch the boundary rotate into place and the loss curve fall. Then try a huge learning rate η (it oscillates) and a tiny one (it crawls).

7. Many classes: softmax

The problem it solves

The sigmoid answers yes/no (2 classes). But often there are K classes: which digit (0–9) is in this image? Which word (out of ~50,000) comes next? We then need K probabilities that are all ≥ 0 and add up to 1. Softmax is the function that produces them.

Building it in four steps

  1. One score per class. Compute K logits z₁…zK, each its own linear score zk = wk·x + bk (think: K logistic-regression neurons side by side).
  2. Problem: raw logits can be negative and do not sum to 1, so they are not probabilities. We cannot simply divide by their sum (negative numbers would break it).
  3. Exponentiate: ez is always positive, and a bigger logit still gives a bigger number.
  4. Normalise: divide each by the total, so the results sum to exactly 1.
softmax(z)k = ezk / ( ez1 + ez2 + … + ezK )

Worked example: logits (2, 1, −1)

e² = 7.39, e¹ = 2.72, e−1 = 0.37. Sum = 10.48. Probabilities: 7.39/10.48 = 70.5%, 2.72/10.48 = 25.9%, 0.37/10.48 = 3.5%. Sums to 100%. ✓

Why the name “soft max”?

A “hard” max would give the winner 100% and everyone else 0: (1, 0, 0). That throws away information (how close was the runner-up?) and has zero gradient, so we could not train with it. Softmax is a smooth, differentiable max: the largest logit gets most of the probability, the others keep a share. Exponentiating also amplifies gaps: a logit 1 higher makes a class e ≈ 2.7× more likely.

Key terms
Logits
The raw scores, one per class, before softmax.
ez (exponential)
e ≈ 2.718 raised to the power z. Always positive; grows very fast.
Normalise
Divide by the total so the values add up to 1.
One-hot vector
The true label written as a vector with a 1 for the correct class and 0 elsewhere, e.g. class B = (0, 1, 0).
Temperature
A number that sharpens (T < 1) or flattens (T > 1) a softmax distribution.

Useful properties

  • Order is kept: the biggest logit is always the most probable class.
  • Only differences matter: adding 100 to every logit changes nothing.
  • Sigmoid is softmax with 2 classes: softmax of (z₁, z₂) gives class 1 the probability σ(z₁ − z₂).
  • Temperature T (drag the slider): logits are divided by T. Low T → sharper, nearly “hard” max. High T → flatter, more random.
  • Training: same cross-entropy as before, L = −log p̂correct, and the gradient is again simply p̂ − y (with y as a one-hot vector). Nothing new to learn.
Transformer linkSoftmax appears twice in a Transformer: (1) at the very end, turning the logits over the ~50,000-word vocabulary into next-word probabilities (the “temperature” you set when sampling from ChatGPT is exactly the T here); (2) inside attention, where softmax turns similarity scores between words into weights that sum to 1 (“how much should I look at each word?”).
How to read this graph
  • Three classes A, B, C. Each bar is the probability softmax gives to one class; the three bars always add up to 100%.
  • Under each bar: its logit z (the raw score you set with the slider).
  • Raise one logit: its bar grows and the others shrink, because they share a total of 100%.
  • Temperature T divides all logits before the softmax: small T → one bar takes almost everything (confident); large T → bars become equal (uncertain).
  • The grey box shows the three computation steps with your numbers: divide by T, exponentiate, divide by the sum.

8. Full code (NumPy, from scratch)

import numpy as np
sigmoid = lambda z: 1 / (1 + np.exp(-z))

def train(X, y, lr=0.3, steps=500):
    w, b = np.zeros(X.shape[1]), 0.0
    for _ in range(steps):
        p = sigmoid(X @ w + b)            # forward pass
        loss = -np.mean(y*np.log(p+1e-9) + (1-y)*np.log(1-p+1e-9))
        gw = X.T @ (p - y) / len(y)       # gradient = (p - y) * x
        gb = np.mean(p - y)
        w -= lr * gw; b -= lr * gb        # update
    return w, b
